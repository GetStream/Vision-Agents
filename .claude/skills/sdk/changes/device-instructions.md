`instructions` is now server-side only (AI-937), on every path a session takes it: `createSession`, the session socket's start frame (`openSocketSession`), `forkSession`, and the events socket's (`watchSession`) `instructions` command. `updateSession` already refused it. From an end user's device, `createSession` and `forkSession` answer a 403, code `forbidden`, type `permission`, message `a session's instructions are changed server-side, never by a device: …`. The session socket answers an `error` frame with the same `error`, `code` and `error_type`, then closes with 1008. The events socket keeps the connection and changes nothing: it sends an `error` frame `{context: "command", error: <the same message>}`. A backend is unchanged on all four. Only descriptions changed in the spec: Go and JavaScript have the regenerated client and types. Python (`plugins/stream`), .NET, Ruby, Rust and PHP pick up the descriptions when they regenerate. With a server credential they may keep sending `instructions`. Python with a user token must not: `sessions.py` sends it on create, on fork and in `set_instructions`. Swift, Kotlin and Dart must stop sending `instructions` from a device, or document the field and method as backend-only. Kotlin: `SessionOptions.instructions` and `ForkOptions.instructions` (`Options.kt`, sent by `Sessions.kt`), and `AgentSession.setInstructions` (`Command.Instructions`). Swift: `SessionOptions.instructions` (`VisionAgents.swift`), `ForkOptions.instructions` (`Models.swift`), and `AgentSession.setInstructions`. Dart: `SessionOptions.instructions` and `ForkOptions.instructions` (`models.dart`, sent by `convert.dart`), and `AgentSession.setInstructions`. JavaScript in a browser (a token) must not pass `instructions` to `Session.fork`, to an `Agent`, or to `session.setInstructions`. Instructions belong in the agent config, or are set by the backend through `updateSession`.
