The router forwards direct calls to a connection's provider (T44, AI-873): `ANY /v1/agents/connections/{id}/proxy/{path}`, declared as five operations `proxyConnectionGet`, `…Post`, `…Put`, `…Patch` and `…Delete`, all server-side only. The request goes to the connector's `api_base` with `{path}` appended (it may hold slashes), with the connection's credential in place of the router's own headers and query parameters, and the provider's answer comes back as it came; a provider's 429 also holds the connection's further calls here until its `Retry-After` passes (429 `rate_limited`). It is meant for a provider's own SDK pointed at the URL as its base URL, so no SDK should wrap it beyond the generated method. The generated method escapes a slash in `{path}` to `%2F`, so it reaches a single-segment path only (`chat.postMessage`, not `repos/octo/hello/issues`); `POST`, `PUT` and `PATCH` take an optional body of any media type. `ConnectorAuditAction` gains `proxy_call`, and `ConnectorAuditEvent` gains `status_code`, `latency_ms` and `target` (the host), set only on a `proxy_call` row. Go and JavaScript have the regenerated client and types. Python (`plugins/stream`), .NET, Ruby, Rust and PHP need their generated clients regenerated and the three audit fields on their model. Swift, Kotlin and Dart need nothing, since none is client-accessible.
