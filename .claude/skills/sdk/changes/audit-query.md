The router keeps an audit log of who changed the app's configuration. `queryAudit` (`POST /v1/audit/query`, cursor paged, an `AuditQuery` `{filter, limit, cursor}` whose `AuditFilter` takes `resource_type`, `resource_id`, `agent_id`, `source` and `action`, answering an `AuditPage` of `AuditEntry` `{id, resource_type, resource_id, resource_name, agent_id, action, source, actor_id, actor_name, request_id, changes, created_at}`, each `AuditChange` `{field, before, after}`) and `getAgentChanges` (`GET /v1/agents/configs/{id}/changes`, answering an `AgentChanges` `{items, last_change, synced_at}`) are server-side only. `AuditResourceType` is `agent_config`, `skill`, `knowledge`, `knowledge_url`, `router_config`, `plugin` or `policy` -- configuration only, never a session or a run; `AuditAction` is `created`, `updated`, `deleted` or `synced`; `AuditSource` is `dashboard`, `cli`, `sdk` or `api`, read from the `X-Stream-Client` header, with `X-Stream-Actor-Id` and `X-Stream-Actor-Name` naming the person behind a client that signs its users in. Every SDK should send `X-Stream-Client` on every request, which is the whole of what one that syncs on startup has to do; Go does it in `Backend.Credentials`. `SyncAgentRequest` also gains `check_changes` and `base_change`: a sync asking to be checked is refused with a 409 `unsynced_changes` rather than writing over an edit made since the last sync, and a client shows the changes and syncs again with `base_change` once the person has decided. Name the methods `audit.query(filter)` and `agents.changes(id)`. Go has the regenerated client (`QueryAudit`, `GetAgentChanges`) and sends the client header; JavaScript has the regenerated types. Python (`plugins/stream`), .NET, Ruby, Rust and PHP need their generated clients regenerated, the client header on every request, and the two methods added. Swift, Kotlin and Dart need nothing, since neither operation is client-accessible.
