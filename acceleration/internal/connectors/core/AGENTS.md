# internal/connectors/core

The contracts every connector adapter implements: `Scheme`, `ToolSource`, `EventSource`, `Toolset`, `CredentialStore`, `Resolver`, `Verifier`, `Hook`, the `Registry`, and the value types they pass, plus the provider manifest model (`manifest.go`): parsing, validation, endpoint templates, and the capture and identity rules, all pure functions, and `Transports` (`transport.go`), the one way a connection's request leaves the router. No adapter implementation lives here. `doc.go` states the rule the rest of this file expands on: adapters import `core`, `core` imports no adapter.

## Terms

One word, one meaning, in code, docs and API alike. A name follows the Go auth libraries where they have one (`golang.org/x/oauth2`, `cloud.google.com/go/auth`, `aws-sdk-go-v2`, Azure `azcore`), and the OAuth and MCP specs where they name the concept. A name never reuses a word that already means something else here: "grant" is only `ToolGrant` and, in prose, the OAuth authorization grant; "backend" is only the customer's server.

## Rules

- **Core imports no adapter.** Schemes, tool sources, credential stores, verifiers (`verifiers/<kind>`) and providers live in their own packages under `internal/connectors/` and import `core`. `TestCoreImportsNoAdapter` fails on any import under `internal/connectors/` outside `core`.
- **Core names no provider.** No string literal in a non-test file may be a provider name from `deniedNames` in `guard_test.go`, or a connector id seeded from `internal/connectors/providers/*.yaml`. Provider specifics go in a manifest or an adapter. `TestCoreNamesNoProvider` enforces it. When you add a name to `deniedNames`, add where it comes from to the comment above the list.
- **Keep the imports small.** `core` imports neither `store` nor `harness`, so `store` can import `core`; tools are `llm.Tool`. Check with `go list -deps ./internal/connectors/core | grep -E 'internal/(store|harness|llmrouter)'`, which must print nothing.
- **Secrets never print.** `AccessCredential` keeps its secret unexported and redacts it in `String` and `GoString`. `StoredCredentials` redacts `Payload` in `String`, `GoString` and `LogValue`. A new type that carries a secret does the same, with a test in `scheme_test.go` covering `%v`, `%+v`, `%#v`, `%s` and both slog handlers.
- **`Scheme.Wrap` sits on top of egress.** The `base` a scheme wraps is the transport `egress.NewClient` hands its `wrap`, so the scheme sees the final request and the egress address check runs under it, at dial. `Transports` builds every connection's client that way (see Transport); build connector clients no other way.
- **A failed `Retrieve` or `Revoke` says what it means.** A scheme returns `*OutcomeError` with the `Outcome` its `Classify` gave the provider's answer, so the resolver reads the kind with `errors.As` and never parses a scheme's error text. An error without one is a bug in the caller's input (unreadable stored credentials, a missing client), or a sentinel the scheme documents for an answer no retry changes, not an outcome to act on. A `Retrieve` whose renewal failed before the old access credential expired, and that the provider had not refused (`RetrieveOptions.Refused`), returns that credential beside the error, with no `StoredCredentials`: the resolver may use it for the call and still act on the outcome.
- **Every hardcoded value says where it comes from**, in a comment next to it, as `deniedNames` does.
- **A manifest is substitution and lookup, never a language.** Endpoints are `{name}` templates over inputs, `vars` and `{metadata.<capture>}`; values are read by a JSON path of member names or a callback query key. What that cannot say is a named hook at one of the three points in `hook.go` (architecture doc, «Risks» items 1 and 3). Do not add conditionals, functions or string operations to templates or paths.
- **Untrusted values cannot steer a request.** An input or a captured value goes into a template only as unreserved characters (RFC 3986 §2.3) that are not a dot segment (`.` or `..`, §3.3). Only a captured value with `host_suffixes` can be the whole origin a template starts with; it is stored as `scheme://host`, a DNS name under one of the suffixes, with no IP literal, port, path, query or fragment. A captured URL that keeps its path (an account id, or a URL a later request fetches) has `host_suffixes` and `keep_path: true`, and is never written into a template. `Apply` refuses a dot segment as a captured value or an identity part, so stored metadata and account ids never hold one. No captured value sits anywhere else in the host, and a callback query value never does. Every input has an enum or a pattern. A resolved endpoint is https with no userinfo, query or fragment. An `id_token` is read only from the token response, never from a callback. An account id built from a callback value is unverified; when the provider's account is what the connection was created for (a Shopify shop), identity names the input and a hook compares the callback to it.
- **Endpoint roles are names, not an enum.** Any lowercase identifier is a role; the ones adapters read are listed on `Manifest.Endpoints`. `resource` is the RFC 8707 resource indicator `oauth2_code` sends when a manifest pins its endpoints (`internal/connectors/schemes/oauth2code/AGENTS.md`); it renders like any endpoint, so it is https with no query or fragment, which RFC 8707 §2 allows.
- **No YAML anchors or aliases.** `ParseManifest` refuses them, so a manifest a customer uploads cannot expand one node into many.
- **Manifest enums are closed and say where their values come from.** A new `from`, `auth_method`, `per`, `alg`, separator or hook point is a change to `manifest.go` with its source beside it, and fixtures in `testdata/manifests/` follow the same rule per field. Scheme and source names are not enums here: they are registry names, checked by whoever holds the `Registry`.

## Manifest

A manifest has `sources`, a `channel` block, or both: Linear has only `sources`, Telegram and Linq only `channel`, Slack and WhatsApp both. `sources` is what tools run against; `channel` is what the provider's inbound requests say: messages a person wrote (an inbound channel), signals about grants, or both. An inbound channel is never a kind of tool. The channel block lives in `channel.go`; `Manifest.Validate` checks it with the rest.

| Term | What it is | In code |
| --- | --- | --- |
| channel block | How a provider's inbound request is verified, where it keeps each message and each signal, and how a reply goes back | `ChannelRule`, manifest `channel` |
| signal rule | One kind of event that says a grant ended, and where it names the account | `SignalRule`, manifest `channel.signals[]` |
| subscription | An event type, as the provider names it, that a provider app the router creates (`managed`) asks to be delivered. Not what messages and signals match on: Slack delivers `message.channels` and `message.im` as `event.type` `message` | `ChannelRule.Subscriptions`, manifest `channel.subscriptions[]` |
| verifier kind | The registered verifier that checks the request, and the parameters it reads | `VerifierRule.Kind`, the key in `Registry.Verifiers` |
| secret source | Whose secret the verifier checks with: the operator's provider app (one for every customer), or the customer's own | `SecretSource`: `operator`, `provider_app` |
| routing key | The path of the provider unit: what picks the connection when one URL serves many customers | `messages.provider_unit_id` → `InboundMessage.ProviderUnitID` |
| thread key part | One named value the thread key is built from, which a reply names as `{thread.<name>}` | `messages.thread_key[]`, `ChannelMessage.ThreadParts` |
| reply window | How long after the person's last message free text may be sent, and the body sent after it | `reply.window`, `reply.after_window` |

`messages` fields are named for the `InboundMessage` field they fill: `provider_unit_id`, `thread_key`, `author_id`, `provider_message_id`, `text`. One concept, one name, in YAML and in `signal.go`.

- **Messages and signals are each optional, not both.** `messages` and `reply` go together; a block with neither has `signals`. The built-in user-token Slack connector (`providers/slack.yaml`) has signals and no messages: nobody writes to it, and Slack tells it about revoked grants.
- **A signal names identity parts, never a joined account id.** `signals[].identity` maps names from the manifest's `identity` to paths, and `Read` returns them as `Signal.Identity`. All parts name one account; fewer name every account that has them (Slack `app_uninstalled` names the team and no user). The reader matches each part where the connection keeps it, an input or a captured value, so no id is ever split on the `:` it was joined with. `match` is required (without one every delivery would be the signal) and names no `[*]`; `each` makes one signal per element, and elements that name the same account are one signal. Check: `go test -run 'TestChannelSuite/(TestARevok|TestASlackUninstall|TestAnUninstall|TestABlockWith|TestASignal)' ./internal/connectors/core`.
- **A signal can say when the event happened.** `signals[].at` is the path of whole Unix seconds (Slack's `event_time`), read into `Signal.At`; it has no `[*]`. `Resolver.Revoke` leaves a connection a consent connected after it, so a provider's retry that arrives after a reconnect does not end the new grant. Without `at` a signal revokes as before. Check: `go test -run 'TestChannelSuite/TestASignal(Says|RuleWithout|Time)' ./internal/connectors/core`.
- **Paths are lookup, one syntax for JSON and form.** A path is member names, each optionally followed by `[*]` (every element) or `[n]` (one element). Every path is also an RFC 9535 JSONPath, with no filters, slices or descendants. JSON: `$.entry[*].changes[*].value.messages[*].from` (WhatsApp). Form: `$.MessageSid` (Twilio posts `application/x-www-form-urlencoded`); a form is one flat object of its fields, so its paths are one member, and a field given twice is an error.
- **A batch is one message per `each` element.** `messages.each` is the path of every message, ending in `[*]`. A `[*]` in another path stands for the same element as the `[*]` at the same place in `each`, so `$.entry[*].changes[*].value.metadata.phone_number_id` is the number of the change that holds that message. `Validate` refuses a `[*]` that is not where `each` has one. Without `each`, the body is one message.
- **What is not a person's message is not read.** A message without its author, id, thread key parts or declared provider unit is skipped, as is one that differs from `match` (exact strings, such as Linq's `event_type` or Slack's `event.type`) or has a `skip_if_present` path (such as Slack's `bot_id`). This is how the bot's own messages stay out. Retried deliveries are the bridge's to drop, by `ProviderMessageID` (T57).
- **A delivery may name its own id.** `channel.event_id` is paths of the provider's id for one delivery, tried in order, with no `[*]`. `ChannelRule.DeliveryEventID` reads it; the forward to an event destination is keyed by it (`internal/eventforward`). A body the block's format does not read is read as a form, and a form field holding a JSON object is read as that object, so `$.payload.trigger_id` reaches the id in a Slack interaction (a form whose `payload` is JSON) on a `json` block. That is the one place a form path goes past one member. Check: `go test -run 'TestChannelSuite/(TestADelivery|TestAnEventID)' ./internal/connectors/core`.
- **A thread key part may fall back.** `fallback` is read when `path` is absent: a Slack message that starts a thread has no `thread_ts`, and its own `ts` is the thread's. That is the only alternative a path has.
- **The thread key is built, never parsed.** `Read` joins the parts with `:`, after percent-encoding `%` and `:` in each, so two threads never share a key. The bridge keeps `ThreadParts` with the thread link; a reader that holds only an `InboundMessage` gets them back with `Read` on its `Raw`, by `ProviderMessageID`.
- **Reply templates follow the endpoint rules.** `reply.url` is an https template like an endpoint's, and may also name `{provider_unit_id}` (only when the block reads one) and `{thread.<name>}`, outside the host; such a value goes in as unreserved characters that are not a dot segment, as an input does. `{text}` is never in the URL. `reply.body` and `reply.after_window` are JSON whose strings may name `{text}`, those values, an input, a vars entry or `{metadata.<capture>}`; `encoding/json` escapes them. A name a template does not declare is refused with its field. No secret is ever in a template: a scheme adds the credential, last.
- **A 2xx is not always a sent reply.** `reply.accepted` is values the answer's JSON must have, compared as exact strings, such as Slack's `$.ok: "true"`: chat.postMessage answers a refusal with HTTP 200 and `ok: false`. `ReplyRule.Accepts` reads it; without `accepted` every 2xx is sent. Check: `go test -run 'TestChannelSuite/(TestAReplyIsSent|TestAReplyWithoutAccepted|TestAnEmptyAccepted)' ./internal/connectors/core`.
- **`Read` needs no connection.** It is a method of `ChannelRule`, so a webhook that one provider app shares among customers is read before its provider unit picks the connection (T39). `Reply` is a method of `ResolvedManifest`, since it fills inputs and captured values.
- **Closed enums, with their sources beside them in `channel.go`:** verifier kinds `hmac_header`, `secret_header`, `standard_webhooks`, `ed25519`; secret sources `operator`, `provider_app`; signal kinds `revoked`, `uninstalled`, `rotated` (`signal.go`); formats `json`, `form`; HMAC algorithm `sha256`, encoding `hex`; signed-template names `{body}`, `{timestamp}`. Each kind takes only its own parameters: `hmac_header` a header, algorithm, encoding, optional prefix, a `signed` template with `{body}` once, and `timestamp_header` with `max_age` when it signs a timestamp; `secret_header` a header only; `standard_webhooks` `max_age` only, the rest is the specification's. `ed25519` takes `hmac_header`'s header, `signed`, `timestamp_header` and `max_age`, and no algorithm, encoding or prefix: the signature is base64 Ed25519 (Telnyx). An `operator` secret needs `client.env`.

Fixtures: `testdata/manifests/slack_bot.yaml`, `linq.yaml`, `telegram.yaml`, `whatsapp.yaml`, each citing the provider page beside every value, with synthetic events in `testdata/recorded/`. Fixtures are data: the guard test reads only non-test Go files outside `testdata`.

## Verifier

`Verifier.Verify(r, body, m, secret)` (`signal.go`) checks one inbound provider request and returns a `VerifiedEvent`. The events endpoint (`internal/api/connector_events.go`, T26) acts on it; the channel bridge (AI-866) reads its messages. `verifiers/hmacheader` is the first verifier, registered in `Registry.Verifiers` under its kind.

| Term | What it is | In code | Reader |
| --- | --- | --- | --- |
| verified event | Everything one verified request says | `VerifiedEvent` | the events endpoint |
| signal | What happened to the grants of an account: revoked, uninstalled, rotated | `VerifiedEvent.Signals`, `Signal` | `Resolver.Revoke`, for each connection of the account |
| inbound message | One message a person sent on an external thread | `VerifiedEvent.Messages`, `InboundMessage` | the channel bridge |
| provider unit | The customer's own unit at the provider that received a message: a workspace, a team, a bot, a business phone number | `InboundMessage.ProviderUnitID` | the bridge maps it to a connection |
| thread key | The id of one external thread within one provider unit, built by the verifier, never parsed | `InboundMessage.ThreadKey` | the bridge maps it to a thread channel |
| provider message id | The provider's id for one message: WhatsApp `messages[].id`, Slack `event.ts`, Twilio `MessageSid` | `InboundMessage.ProviderMessageID` | the bridge finds the message's entry in `Raw` by it and drops retried deliveries by it |
| challenge | The value a handshake request asks the endpoint to send back | `VerifiedEvent.Challenge` | the endpoint answers 200 `text/plain` with it |

- **A manifest and a secret, no connection.** `m` is the connector's `Manifest`, since a request is verified before anything picks a connection. `secret` comes from the route: the operator's on a connector's route (`<client.env>_MCP_SIGNING_SECRET`, `api.ConnectorEventSecrets`), a provider app's on its own route (`POST /v1/connectors/events/{connector_id}/{provider_app_id}`, `api.receiveProviderAppEvent` with `api.ProviderApp`, T38). A verifier never looks a secret up.
- **An error means nothing happens.** A request that fails verification returns an error and the endpoint acts on no part of it. A verified request the verifier has no mapping for returns a zero `VerifiedEvent`, not an error, and so does a verified body the verifier cannot parse.
- **Slices, not single values.** One revocation event can name several tokens, and one delivery can batch several messages, so `Signals` and `Messages` are slices. A handshake sets only `Challenge`.
- **The raw body is bytes.** `body` is read once, before anything parses it, because a signature covers those exact bytes. `InboundMessage.Raw` is that body unchanged, shared by every message of a batch, and `[]byte`, not `json.RawMessage`, because some providers post a form. `ProviderMessageID` tells the messages of a batch apart.
- **Ids stay the provider's.** A `Signal` names an account and an `InboundMessage` names a provider unit, an author and a message, all as the provider sends them. Mapping them and the thread key to a connection, a thread channel or a Stream Chat user is the reader's job, not the verifier's.

## Resolver

`Resolver` (`resolver.go`) is the one door to an access credential: every tool source, the proxy and the channel bridge ask it, and none opens a `CredentialStore` or calls a token endpoint. The router's implementation is `internal/connectors/resolver`, whose `AGENTS.md` has the flow and the cache rules.

| Term | What it is | In code |
| --- | --- | --- |
| checkpoint | A commit of the credential state, under the lock, before a request that cannot be taken back. The resolver decides what it commits (`needs_reauthorization`); the scheme decides when | `CredentialStore.Update`'s `checkpoint`, handed to `Scheme.Retrieve` as `RetrieveOptions.Checkpoint` |
| valid until | When the access credential must still work: the call's deadline, handed to the scheme. A scheme that can renew renews a credential that expires at or before it | `RetrieveOptions.ValidUntil`, from `CredentialRequest.Deadline` |
| revision | The number of the stored credentials a connection holds. The credential store advances it by one with each new stored credentials and leaves the committed one in `state.Revision`; nothing else computes it | `CredentialState.Revision`, `AccessCredential.Revision` (set by the resolver), column `revision` |
| detached refresh | `Retrieve` on a context of its own, with its own deadline, so a caller that gives up does not leave a refresh half done | `CredentialRequest.Deadline` is the call's budget, not the refresh's |
| refused | The access credential the provider just refused on a call. The resolver serves none from its cache and, while the stored credentials still hold it, has the scheme renew it whatever its expiry | `CredentialRequest.Refused`, handed to `Scheme.Retrieve` as `RetrieveOptions.Refused` |
| invalidate | A caller saying the provider refused the credential (`invalid_grant`) or wants more access (`scope_required`) and nothing renews it. It names the refused credential, so a refusal of one that had expired or that another router already replaced moves no status | `Resolver.Invalidate(ctx, ref, rejected, why)` |
| revoke | A verified provider event saying the grant ended (a `Signal`). It names no credential: a connected connection moves to `needs_reauthorization` under the lock whatever revision it is at, unless a consent connected it after the signal's `endedAt` (`CredentialState.ConnectedAt`, column `connected_at`) | `Resolver.Revoke(ctx, ref, why, endedAt)` |

- **A scheme calls `RetrieveOptions.Checkpoint` right before a request it cannot take back**, such as spending a rotating refresh token, and sends nothing if it fails. Only the scheme knows whether its `Retrieve` renews: the connection's expiry is unknown until its first `Retrieve` (`internal/api/authorizations.go` stores it zero after a consent), and the margin is the scheme's. A nil `Checkpoint` has nothing to commit, so a test can call `Retrieve` with `RetrieveOptions{}`. Check: `go test -run 'TestOAuth2CodeSuite/(TestARefreshCheckpoints|TestARefreshWhoseCheckpoint|TestAccessCredentialThatIsNotDueNever)' ./internal/connectors/schemes/oauth2code`.
- **A scheme that can renew renews a credential that expires at or before `RetrieveOptions.ValidUntil`**, as well as one inside its own margin, so a call does not start with a credential that dies during it. A scheme whose credential never expires returns it as stored. Check: `go test -run 'Contract/TestACredentialThatExpiresBeforeValidUntilIsRenewed' ./internal/connectors/schemes/...`.
- **Statuses are the store's** (`store.ConnectionConnected`, `ConnectionNeedsReauthorization`, `ConnectionDisconnected`, `ConnectionPending`); `CredentialState.Status` holds one of them.

## Transport

`Transports` (`transport.go`) builds the one outbound client of each connection with `egress.NewClient(timeout, wrap)`. Its `wrap` resolves the access credential for each request and hands it to `Scheme.Wrap`. A tool source gets the client as `ResolvedBinding.HTTP` and sends with it as it is.

```
client.Do(request)             the egress client of one connection
  redirect policy              egress: same origin, same method, at most 10
  URL check                    egress: https, a host, no userinfo
  credentialed                 Resolver.Resolve(ref, Deadline: request ctx)
  Scheme.Wrap                  header or signature over the final request
  URL check again              egress: on what Wrap produced
  dial                         egress: only a checked public IP
  a 401                        Scheme.Classify(response, first 1 MiB, err)
    invalid_grant,             Resolve(ref, Refused: sent credential)
    scope_required               renewed past it (a refresh, or what another
                                 router renewed), body can be read again
```

- **Only egress builds the client.** `TransportsConfig.NewClient` is `egress.NewClient` when nil, which is what the router runs; a test sets it to reach a loopback fake, which egress refuses. A source never builds a client: the credential is applied only inside the one `Transports` gives it, so a client of its own carries none. Check: `go test -run 'TestTransportsSuite/TestAPrivateDestination' ./internal/connectors/core`.
- **The scheme sees the request that leaves.** `Content-Length` and the body digest it signs are those of the bytes on the wire, and the egress dial check runs after it. Check: `go test -run 'TestTransportsSuite/(TestAPrivateDestination|TestTheProviderReceivesTheBody)' ./internal/connectors/core`.
- **The redirect policy is egress's.** `ResolvedBinding.HTTP` is an `*http.Client`, not a `RoundTripper`, because the policy that keeps a redirect in its origin lives on the client. A hop to another origin never reaches `Wrap`. Check: `go test -run 'TestTransportsSuite/(TestACrossOrigin|TestASameOrigin)' ./internal/connectors/core`.
- **A credential per request.** Each request asks the `Resolver`, with its context's deadline as `CredentialRequest.Deadline`. `http.Client` puts its `Timeout` on that context, so without a deadline of the caller's, the timeout is the budget. The resolver's fast path makes this cheap (`internal/connectors/resolver/AGENTS.md`, «Cache»); a refused `Resolve` sends nothing. Check: `go test -run 'TestTransportsSuite/(TestEachRequest|TestTheRequestsDeadline|TestAResolverRefusal)' ./internal/connectors/core`.
- **A 401 renews first, and is sent again at most once.** Only a 401 is classified, as the design says (`docs/connectors/channels.md` on `connectors/planning`, «The proxy»: «On a 401 the Router calls Invalidate, refreshes and retries once»). A refused credential may belong to a grant that still works: the provider's clock runs ahead, or it ended the access token early. So the transport first asks for a credential renewed past the refused one (`CredentialRequest.Refused`, which reaches the scheme as `RetrieveOptions.Refused`); only a refused renewal, as with any failed renewal, moves the connection. The request goes again when the body can be read again (`GetBody`). `Invalidate` is called only when nothing renews the credential (a static key, a token with no refresh token) or the renewed one is refused too, with the credential that was sent. Example: an `oauth2_code` token the provider ended an hour early is refreshed, the call succeeds, the connection stays connected; with a refused refresh it moves to `needs_reauthorization`. A 403 `insufficient_scope` is returned as it is: a scope one tool lacks says nothing about the others. Check: `go test -run 'TestTransportsSuite/(TestARefused|TestARefusal|TestABodyThat|TestA401)' ./internal/connectors/core`, `go test -run 'TestOAuth2CodeSuite/(TestARefusedAccessToken|TestAFailedRefreshOfARefused)' ./internal/connectors/schemes/oauth2code` and, with Postgres, `go test -tags integration -run TestTransportSuite ./internal/connectors/resolver`.
- **One client per connection, a copy per caller.** `Transports.Client` builds the client once per `ConnectionRef` and returns a copy that shares its connection pool, so a caller that replaces its copy's `Transport` changes nothing for the others. `Transports.Close(ref)` drops it and closes its idle connections, for the delete and disconnect paths to call. `cmd/router` builds one `Transports` and hands it to the API (`api.Options.ConnectorTransports`), whose validate endpoint is one caller; the session's dispatcher (`session.ManagerOptions.Connectors`) shares it, and `deleteConnection` calls `Close`. A copy held past `Close` still asks the resolver first, which refuses a connection that is gone. A client nothing asked for or sent with for `idleAfter` (90 s, `DefaultTransport`'s `IdleConnTimeout`, by when it holds no idle socket) is dropped the next time a client is built, at most once per `idleAfter`, so every replica forgets connections it no longer uses. Check: `go test -run 'TestTransportsSuite/(TestOneConnection|TestClosing|TestReplacing|TestAClientUnused)' ./internal/connectors/core` and `go test -tags integration -run TestTransportSuite/TestAClientHeldPastADelete ./internal/connectors/resolver`.
- **`Retrieve` can run before egress refuses.** The dial check comes after `Wrap`, so a refresh for a host that resolves to a private address still runs; the token never leaves the router. When `Retrieve` itself must not run, call `egress.ValidatePublicHTTPSURL` on the endpoint first.
- A scheme's TLS client certificate (`mtls`, `tls_scheme`) is not built yet; it belongs to this one client per connection.
- **A request records what it saw for whoever asked (`Exchange`, `records.go`).** A context made by `WithExchange` gets told whether a request left with a credential, the provider's last status, the `Resolver`'s refusal and a client timeout; nothing else is kept, never a header, a body or a credential. The session's dispatcher reads it to say how a tool call failed in the invocation log, because a tool source's error does not say whether anything was sent and the MCP client reports a 401 only as its status text. A context without one records nothing. Example: a provider answering 401 to a call is `customer_auth`; arguments the source refuses before sending are `denied`. Check: `go test -tags integration -run TestInvocationLogSuite ./internal/session`.
- **Who caused a grant change rides on the context (`Correlation`, `records.go`).** The API puts the request's `X-Request-Id` on every request's context, and the session's dispatcher adds the session's id, both when a binding is opened and when a tool is called; the resolver copies both onto the audit rows it writes. A session's turns run on the context of the request that created it, so for an incognito session the dispatcher drops the request id too, on open and on call, and its rows carry neither. Check: `go test -tags integration -run TestResolverSuite/TestAuditOfARefreshIsOne ./internal/connectors/resolver` and `go test -tags integration -run 'TestInvocationLogSuite/Test(AnIncognito|ARecorded)' ./internal/session`.
