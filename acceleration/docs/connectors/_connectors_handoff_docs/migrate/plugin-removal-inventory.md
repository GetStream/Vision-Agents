## (a) DB objects a contract migration would drop
- Tables: `agent_plugin_connections` (3 indexes), `agent_plugin_clients`, `agent_plugin_event_subscriptions` (2 indexes), `agent_plugin_event_deliveries`.
- Columns on `agent_configs`: `plugins`, `plugin_events`. Also `plugin_options` if it still exists (unverified).
- CHECK on the audit table (`20261008120000_audit_log.sql` :30): `plugin` in the `resource_type` list. Old rows with `plugin` must stay valid or be rewritten.
- Already dropped: `user_plugins`. No other plugin tables found in `acceleration/migrations`. Also check `connections.go`/`datamove.go` for table-name lists, which I did not verify.

## (b) Must go in one PR
- Router route removal, `plugins.go` handlers, the OpenAPI paths and schemas, and the regenerated SDKs/`plugins/stream`/volt `src/gen` types. The spec check and client regeneration are enforced together.
- `internal/plugins`, `pluginevents`, `session/plugin_tools.go`, `spec.go` `withoutBoundPlugins`, `conversation/authorizations.go` and the `server.go`/`main.go` wiring. These share types (`plugins.Authorization`, `plugins.Auth`).
- `store/plugins*.go`, models, and the contract migration. The migration must not run before the code stops reading the tables.
- `pluginmigrate`, `cmd/router/plugins.go`, `oauth2code/move.go` and the provider-yaml migrate comments. Deleting `pluginmigrate` without a prior run on every deployment destroys the only path from plugin to connector.
- In volt, the `plugins` consumers in `connector-bindings` must go together with the router dropping the `plugins` field.

## (c) Suggested PR split, smallest and safest first
1. **Gate** (precondition, no code): run `router plugins migrate --apply` on every deployment and record it. Decide what to do about `plugin_events`, which the migrate command does not move. Without this, nothing below is safe.
2. **volt-dashboard**: delete the SHOW_PLUGINS code. Remove `show-plugins.ts`, `agent-app-setup.tsx`, the `$pluginId` route + routeTree, `use-plugin-login.ts`, `plugin-mark.*`, `ConnectedApps`, the `config-used.tsx` plugin read, `use-test-draft.ts` `/plugins` call, `main.tsx` popup, and `agent-app-setup.test.tsx` plus mock edits. Keep `connector-bindings.ts` helpers for now. No router change needed, since the flag is already false.
3. **Router API deprecation**: stop accepting/returning `plugins`/`plugin_events` on configs, sync and patch. Remove the `pluginAliasComplaint`/`pluginEventsComplaint` checks. Keep the tables. Regenerate openapi, all SDKs, `plugins/stream` and volt types. Update SDK agent.yaml readers (go, js, dotnet, php, ruby, rust) to warn on `plugins:` and the examples/docs.
4. **Router runtime removal**: delete the plugin tools in `session`, `plugins/`, `pluginevents/`, handlers in `api/plugins.go`, the handwritten routes, wiring in `main.go`/`server.go`, and `conversation/authorizations.go` plug types. Replace with the connector equivalents.
5. **Migration tooling removal**: `pluginmigrate`, `cmd/router/plugins.go`, `oauth2code/move.go`, `plugin_migrate_test.go`, provider-yaml comments, `store/plugins*.go`. It may be folded into PR 4 if the DB drop follows.
6. **Contract migration**: drop the four tables, `plugins`, `plugin_events` and `plugin_options` if present. Decide how the audit CHECK treats `plugin`. Run last, after at least one release without readers.
7. **Cleanup**: `connector-bindings.ts` helpers, SKILL.md files, README, `.claude/skills/plugin`.
