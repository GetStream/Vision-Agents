Planner rulings (Kanat may overturn; see Human gates):
- P1 (Kanat 2026-10-20: «проработаем оба варианта … fallback») Two brokers behind one interface `sandbox.CredentialBroker`: wave 13 ships the Daytona Secrets broker (brief «Mechanism»); wave 14 ships the router-hosted egress proxy (Tommaso's literal design) as the provider-independent fallback. Both must pass the same contract and attack suite `internal/sandbox/brokertest` (A1-A14 below). The session knows only the interface, so changing sandbox provider or broker is a router setting, not a rewrite.
- P2 One Daytona secret per (session, binding), name `va_<session id>_<binding name>` (charset per `CreateSecretParams.Name`, types.go:203-205; truncate/hash to fit if a limit applies — check API answer), hosts = the manifest's `sandbox.hosts`. Created when the sandbox is first created (daytona.go `started`), value from `core.Resolver.Resolve`; before each `Run`, Resolve again and `Secret.Update` only when the credential's Revision changed; deleted in `Close`. Leaks from a crashed router are swept in wave 15 (w15-sweep).
- P2b Staging and every local router share one Daytona org (P2 check above), so secret names carry the environment: `va_<env>_<session id>_<binding>`, `<env>` from a router setting (`sandbox.secret_prefix`, staging `stg`, local default `dev_<hostname hash>`). A sweep (w15-sweep) deletes only its own `<env>` prefix; otherwise staging's sweep would delete a developer's live secrets, whose sessions it cannot see.
- P3 The manifest's `sandbox` block is read at the connection's pinned definition revision, like every other manifest field (`core.ResolvedManifest`, resolved_manifest.go:7-9). An existing GitHub connection (revision 5) gets it only after a reconnect; the binding validation says so.
- P4 Opt-in per binding: `sandbox: true` on `AgentConnectorBinding`. Refused when the connector's latest manifest has no `sandbox` block, or the config sets no sandbox provider. Default false = today's behaviour.
- P5 First connector: GitHub only (`github.yaml` revision 6). Hosts: `api.github.com` (REST, [rest] in github.yaml) and `uploads.github.com`; `github.com` (git) waits for w15-git, because git sends Basic auth, which Daytona cannot match (brief). Kanat 2026-10-20: GitHub only, but with thorough tests and attack simulations (A1-A14).
