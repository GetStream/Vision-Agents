Decisions (Kanat, plan approved 2026-10-12; do not re-open):
- Router gets `tool_patterns` on bindings (names or `path.Match` patterns), mutually exclusive with a non-empty `tools`, on session AND fixed bindings. This relaxes «fixed needs schema_digest» (configs.go:549) on purpose: pins are per connection (`connection.ID` + `ConnectedAt`), so trust on first use holds for a fixed connection too. Say so in the PR body.
- agent.yaml `connectors:` entry: a string `linear` → `{name: linear, connector_id: linear, connection: {type: session}, tool_patterns: ["*"]}`; or an object `{name, connector (default name), tools (→ tool_patterns as written), connection (id or label → fixed), required}`. `plugins:` keeps working, its warning says «rename plugins to connectors». `mcp_servers:` unchanged.

Planner rulings (Kanat may overturn; see Questions for the human):
- P1 No migration: bindings are JSONB in `agent_configs.connectors` (store/models.go:386, `ConnectorBinding` models.go:442), so `tool_patterns` is a JSON field (`json:"tool_patterns,omitempty"`). Pins reuse `connector_tool_pins` (20261011150000). Rollback to v0.6.34: `encoding/json` drops the unknown key, the binding reads `tools: []` → grants none (fail closed). Slot 20261018120000 reserved for w9-pat, expected unused.
- P2 The example `examples/text_agents/mcp_plugins/` runs on the Python SDK (`mcp_plugins.py` imports `vision_agents.plugins.stream`), so its agent.yaml rewrite ships in w9-py, not w9-go: before w9-py the Python reader refuses `connectors:` (folder.py:476-478). Go SDK's caller is `agents.Agent.syncFolder` (config.go:61), the path every Go agent with a folder runs (e.g. sdks/go/examples/quickstart).
- P3 `connection: <x>` in agent.yaml is resolved by the SDK at sync: `GET /v1/agents/connections?owner_type=app&connector_id=<connector>` (all pages); an exact `id` wins, else exactly one `label` match; 0 or >1 → error naming the entry. No router change. Labels are not unique (migration 20261002193000:38, `label TEXT NOT NULL DEFAULT ''`).
- P4 Session open for a pattern binding: `Discover` the full list (as `pinGrants` does, connector_tools.go:413-425), match patterns, pin unpinned matches at the listed digest (`PinConnectorTools`), pass the matched tools with their pins as grants to `Open` (which keeps digest == pin, mcp/source.go:121-155). One extra `tools/list` per session per pattern binding is accepted for now (Nit ticket to fold it into Open). More than 128 matches → offer the first 128 by name order and WARN once (cap = `Tools` maxItems 128, configs.go:1759).
- P5 YAML `tools:` absent in an object entry → `["*"]`; `tools: []` → refused by the SDK (a binding that grants nothing is the router's «empty list grants none», not a plugins habit).
