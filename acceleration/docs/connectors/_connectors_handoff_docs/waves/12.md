## Reference (what every SDK PR copies)

- Go is the source of truth: #895 (`29a014f0`), `sdks/go/agents/folder.go:168-300` (`ConnectorSettings`, `connectorList`, `UnmarshalYAML`) and `sdks/go/agents/config.go` (`connectorBinding`, label resolution). Python #896 (`c891381c`) is the second reader. Syntax and rulings P1-P7: `waves/9-current.md` «agent.yaml `connectors:`».
- Shape: a string is a session binding with `tool_patterns: ["*"]`, `tools: []`. An object is `{name, connector, tools, connection, required}`; `connector` empty means `name`; `tools` goes to `tool_patterns` as written; `tools` absent or null means `["*"]`; `connection` set is fixed (exact id wins, else exactly one label via `listConnections`, 0 or >1 is an error).
- Refusals, same wording as Go: null entry `a connector needs a name`; `tools: []` `connector %q: tools: [] grants nothing; leave tools out for every tool`; bad connection `connector %q: connection must be a connection id or label`; unknown keys in an object refused.
- Leaving `connectors` out of agent.yaml sends nothing (stored bindings kept); an empty list sends `[]` (clears).
- Fingerprint: unchanged. It is taken over agent.yaml as written (`folder.go:530`, `fingerprint(f.Declaration, ...)`), so `connectors` is already in it. Each PR confirms its SDK hashes the raw file the same way; no fixture change expected.
- `plugins:` still syncs; Go logs `agent.yaml plugins are deprecated: rename plugins to connectors` (`config.go:69`). Q1.
